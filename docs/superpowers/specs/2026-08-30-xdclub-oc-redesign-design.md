# XDCLUB OC 视觉改造设计

日期：2026-08-30  
状态：用户已批准，待实施  
适用项目：Cloudflare Workers Static Assets 单页网站  
正式域名：`https://xdclub.dpdns.org/`

## 1. 目标与边界

在不重建现有网站、不改变四个纵向全屏分区、不破坏配置、主题、服务入口、页脚、404 或 Worker 安全响应的前提下，将用户提供的 OC 图片融入第一屏，并统一升级色彩、页头、响应式与轻量动效。

本次不增加框架、运行时依赖、登录、会员系统、后台、数据库或第三方脚本。Figma 插件不创建新文件，因为用户未要求交付 Figma 设计稿；设计方向已通过本地可视化预览确认。GitHub 写入和线上部署属于实现完成后的交付步骤，不属于本设计文档提交。

## 2. 已批准的设计选择

- OC 保留原始白色背景，不抠图、不重绘、不改变人物脸部、服装、颜色、比例或身份特征。
- 视觉配色采用“月岩蓝灰”，替换原来的黑曜金主系统。
- 首页采用沉浸式人物层，但不把 2:3 竖图拉伸成横屏背景。
- 图片从原图顶部开始取景并向下落位，完整保护头顶、刘海、双眼、下巴和颈部配饰。
- 桌面、平板、手机和横屏分别设置焦点；正脸完整可见、比例正确、文字不碰撞是硬性验收条件。
- 参考 `QuantumNous/new-api` 当前公共页头的“顶部整合、滚动后缩窄悬浮”交互概念，但不复制其 React/Tailwind 代码、品牌或无关组件。

## 3. OC 素材分析与资产策略

用户提供的源图为 PNG，分辨率 1024×1536，纵横比 2:3，无 Alpha 通道。人物完整站姿位于中右侧，脸朝左，左侧具有大量留白，头发、鞋和主要配饰未贴边。该构图天然适合人物在右、文案在左，并使视线朝向页面内容。

资产结构：

```text
assets/source/oc-character-original.png
public/assets/oc-character-640.jpg
public/assets/oc-character-1024.jpg
```

- 源 PNG 原样保存于非部署源资产目录，不覆盖、不重新编码。
- 因源图无透明通道且背景接近白色，使用高质量 JPEG 衍生图能显著降低传输体积，不引入图片处理依赖。
- 640 像素宽衍生图用于大多数手机；1024 像素宽衍生图用于平板、桌面和高密度显示。
- 使用 `picture`/`srcset`/`sizes` 选择资源，`img` 明确声明 `width="1024"`、`height="1536"`、`fetchpriority="high"` 和 `decoding="async"`。
- 首屏 OC 是主要视觉和潜在 LCP 元素，不使用懒加载。
- 衍生 JPEG 使用足以避免可见块状、色带和边缘毛刺的高质量设置；生成后必须在真实页面截图中检查脸部、头发和服装细线。

## 5. 首页构图

### 桌面与宽屏

- 第一屏仍为 `min-height: 100svh`。
- 文案位于左侧安全区，宽度约占容器 48%–54%。
- OC 图层固定在第一屏右侧，宽度约占 48%–59%，使用独立容器而非整个视口的 `object-fit: cover`。
- 图层左侧以月岩蓝背景渐变融合，避免白色图片背景形成生硬矩形，也不改变 OC 本身颜色。
- 图片保持 2:3 比例，容器裁切使用 `object-fit: cover` 与顶部焦点；不得通过不一致的 CSS 宽高压缩或拉伸。
- 图片图层 `pointer-events: none`，层级低于页头和文案，不得遮挡任何交互元素。

### 平板

- 保持左文右图或轻度重叠的双区结构。
- 文案获得独立对比遮罩，图片焦点优先完整显示脸部与上半身。
- 当横向空间不足时缩短标题最大宽度和图片占比，不通过压缩人物解决空间问题。

### 手机竖屏

- OC 作为全高背景人物层，人物向下落位，优先展示完整正脸和可识别上半身。
- 文案位于下方受控玻璃层或深色渐变区域，不覆盖脸部。
- 页面标题、正文、导航和主题按钮的触控区域不进入人物脸部安全区。

### 手机横屏与矮屏

- 关闭强制滚动吸附，允许内容自然增高。
- 使用紧凑左右布局；必要时减少人物可见范围，但仍保护完整正脸。
- 标题字号和间距降低，页头保持单行，不允许水平溢出。

## 6. 页头与品牌

- 品牌在语义上仍是一个返回首页的链接，视觉上拆为 `XD` 与 `club` 两个相邻 `span`。
- `XD` 使用较高字重和主文字色；`club` 使用略低字重和主题强调色，整体保持紧凑现代无衬线风格。
- 页码导航 `01/02/03/04` 位于页头右侧，保留主题开关。
- 页面处于绝对顶部时，页头铺在内容顶部、左右边距与页面网格对齐、表面接近透明且不显示独立圆角，视觉上与第一屏顶部合并。
- 顶部观察哨离开视口后，页头立即进入贯穿其余页面的悬浮态：外层与视口顶部及左右边缘分离，内部最大宽度缩小，并形成类似 Apple 界面的连续大圆角矩形，而不是圆形按钮或夸张胶囊。
- 悬浮态使用受控半透明表面、细边框、柔和内高光、低扩散阴影和背景模糊；进入第二、第三、第四屏时始终保持该状态。
- 返回绝对顶部时，悬浮容器平滑扩展回页面网格宽度，圆角、外边距、边框、阴影和玻璃不透明度同步减弱，最终重新与顶部融合。
- 两态共享同一个固定定位外壳与同一组导航节点，不插入或移除占位元素；状态切换不会改变文档流高度，因此不得出现页头跳动或内容位移。
- 状态过渡采用约 600–700ms 的 `cubic-bezier(0.16, 1, 0.3, 1)`，动画容器宽度、内外边距、圆角、透明度、边框和阴影；不使用弹跳、过冲或持续滚动计算。
- 只在页头使用较明显 `backdrop-filter`；不支持时回退到较实的主题表面。
- 页头层级高于 OC，玻璃层下的文字在所有分区背景上保持可读。

## 7. 动效与交互

- 使用一个位于页面绝对顶部的观察哨和 `IntersectionObserver` 切换页头两态，避免连续滚动计算；离开顶部即悬浮，重新到顶即合并。
- 使用另一个 `IntersectionObserver` 为标题、主要段落和服务内容添加一次性揭示类。
- 揭示动效仅使用 `opacity: 0 → 1` 和 `translateY: 16px → 0`，时长约 480–620ms。
- OC 初始进入使用轻微透明度与不超过 16px 的纵向位移，不增加持续漂浮、鼠标视差或 3D 旋转。
- 导航、主题按钮和服务链接只使用短促颜色、边框和轻位移反馈。
- `prefers-reduced-motion: reduce` 下禁用平滑滚动、图片位移、揭示位移和非必要持续动画；内容默认可见。
- JavaScript 或 `IntersectionObserver` 不可用时，页头保持稳定、所有内容直接可见，锚点导航仍可使用。

## 8. 现有功能与数据流

以下能力保持不变：

- 四个按顺序排列的全屏纵向分区。
- `site-config.json` 集中配置品牌、首页文字、三个服务和页脚。
- HTML 内置默认文案，配置加载失败时不出现空白页面。
- `textContent` 写入配置文字。
- 服务 URL 只允许绝对 `http:`/`https:`，外链使用 `noopener noreferrer`。
- 主题遵循系统偏好、允许手动切换并安全写入 `localStorage`。
- 第三、第四屏未配置 URL 时保持不可点击。
- 自定义 404、GET/HEAD 方法限制、Workers Static Assets 绑定和现有安全响应头。

新增 OC 不进入配置文件，避免把本地文件路径或任意资源 URL 变成运行时输入。OC 路径是同源静态常量。

## 10. 安全、性能与无障碍

- 不新增 `innerHTML`、内联事件、远程脚本、令牌、环境变量或任意跳转。
- OC 仅作为静态图片，不读取或注入图片元数据，不暴露源文件系统路径。
- 保留 CSP、COOP、CORP、HSTS、MIME 防嗅探、来源和权限策略；新增图片仍来自同源。
- 图片尺寸预留空间以避免 CLS，响应式衍生图减少移动端传输。
- 页头模糊限制在小面积容器，移动端降低模糊半径和阴影复杂度。
- 品牌链接、分区导航、主题按钮、服务链接均保留可见焦点和可访问名称。
- 导航点击区域移动端不得小于现有可用尺寸，并检查 320px 宽度。
- OC 若属于纯品牌装饰，使用简洁且不重复正文的替代文本；不将角色外观描述作为导航信息。
